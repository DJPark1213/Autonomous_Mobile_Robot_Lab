ROS Computation Graph
Ø Nodes
Ø Are executables that use ROS to communicate with other nodes.
Ø A ROS node is written with the use of a ROS client library, such as roscpp or rospy.
Ø Messages
Ø A ROS message is a data structure, comprising typed fields. Nodes communicate
with each other by passing messages. (Structures defined in .msg files)
Ø Topics
Ø Each topic is a message bus that carries a certain type of message.
Ø Multiple nodes can subscribe and publish to a single topic.
Ø One node can subscribe and publish to many topics.

ROS Computation Graph (Cont’d)
Ø Services
Ø ROS Services complements the subscriber/publisher communication model
(Topics), by adding a synchronous request/reply model.
Ø A service provider node offers a service under a name and a client node uses
the service by sending the request message and awaiting the reply.
Ø Bags
Ø Bags are a format for saving and playing back ROS message data.
Ø Example: Storing sensor data to be used later.

Topic Quality of Service (QoS)
Ø ROS2 offers variety of QoS policies for tunning communication between nodes
Ø Can be as RELIABLE as TCP or as BEST_EFFORT as UDP
Ø More info here:
https://docs.ros.org/en/humble/Concepts/Intermediate/About-Quality-of-Service-Settings.html#quality-of-service-settings
Ø Each topic has an associated Reliability policy which it adheres to
(ex: /TTBXX/imu is BEST_EFFORT)
Ø To determine a topic’s QoS: ros2 topic info --verbose [topic_name]

PID - Pseudo Code
previous_error = 0
integral = 0
start:
error = setpoint - measured_value
integral = integral + error*dt
derivative = (error - previous_error)/dt
output = output + Kp*error + Ki*integral + Kd*derivative
previous_error = error
wait(dt)
goto start
